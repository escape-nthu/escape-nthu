# Final Project Proposal：逃離清大

## 一句話 Pitch

《逃離清大：Delta Protocol》是一款發生在清大台達館與資電館的雙人合作 AI 密室解謎遊戲。玩家必須躲避鬼魂、破解演算法題，並透過與 AI NPC 的策略對話找出逃離校園的方法。

## Game Concept

《逃離清大：台達館/資電館仲夏夜之夢》是一款結合 Top-down 探索、雙人合作、密室解謎、AI 對話 NPC 的 2D Web 解謎遊戲。

玩家分別扮演兩位被困在清大校園不同建築中的學生，必須在鬼魂遊蕩的夜晚中探索場景、蒐集線索、解開知識鎖，最後成功逃離台達館與資電館。

平常探索地圖時，遊戲以 Top-down 視角呈現；當玩家與 NPC、AI 角色或重要物件互動時，畫面會切換成類似視覺小說 Visual Novel 的背景與角色立繪，強化劇情與沉浸感。

## Motivation 動機

我們想製作一款不只是單純解謎，而是能結合 AI 對話、程式能力、合作推理與校園場景的遊戲。

密室逃脫遊戲通常依靠固定謎題，但如果加入 LLM 作為 NPC，玩家就不只是點擊物品或輸入密碼，而是需要透過觀察場景、理解線索，並用有策略的對話向 AI 套出關鍵資訊。

清華大學的台達館與資電館對資工系學生來說是熟悉的場景。我們希望把真實校園空間轉化成恐怖解謎地圖，讓玩家在熟悉的地方產生陌生感與緊張感。

目標特色：

- 校園恐怖密室逃脫氛圍。
- 雙人合作解謎。
- AI NPC 對話推理。
- 程式解題與演算法挑戰。
- Top-down 探索結合視覺小說式互動演出。

## User Story 使用者故事

玩家分別扮演 A 男生與 B 男生。某天深夜，兩人因為不明原因被困在清大校園中。

A 醒來時發現自己在台達館，走廊中有鬼魂遊蕩，必須一邊躲避追擊，一邊尋找逃離樓層的方法。B 則被困在資電館，他無法直接與 A 相遇，但能在自己的場景中找到另一部分線索。

玩家需要分工合作：

- A 可能找到密碼提示，但不知道如何解讀。
- B 可能找到對應的公式、程式碼或房間資訊。
- 兩人需要交換資訊，才能解開彼此樓層的謎題。
- 某些門鎖需要兩邊同時完成條件才能打開。

遊戲過程中，玩家會遇到由 AI 控制的 NPC。NPC 不會直接給答案，而是掌握某些關鍵資訊。玩家必須根據場景中的線索，設計正確的問題，透過對話推理出開門密碼、鑰匙位置或演算法題目的提示。

最終，A 和 B 需要完成多個樓層的合作考驗，成功會合並逃離清大校園。

## Setting 遊戲背景故事

午夜的清華大學突然停電，台達館與資電館被未知力量封鎖。

A 和 B 原本只是留下來趕作業的資工系學生，卻發現整棟建築變得異常安靜。走廊中開始出現不明鬼影，教室門上出現奇怪的知識鎖，牆上留下像是演算法題目、課堂筆記與錯誤程式碼的線索。

傳說中，只要在午夜時分無法通過「知識考驗」的學生，就會被困在清大校園的無限樓層中。A 和 B 必須利用自己的程式能力、推理能力，以及彼此合作，找出逃離的方法。

## Controls 操作方式

Top-down 探索模式：

- W / A / S / D：角色移動。
- 滑鼠點擊 / E 鍵：與物件、NPC、門鎖互動。
- Shift：短暫衝刺，用來躲避鬼魂。
- Tab：開啟目前蒐集到的線索筆記。
- Esc：暫停遊戲或開啟選單。

Visual Novel 對話模式：

- 滑鼠點擊：推進對話。
- 文字輸入框：向 AI NPC 提問。
- 選項按鈕：選擇特定回應或追問方向。
- 線索欄位：查看目前找到的關鍵資訊。

雙人合作模式：

- A 和 B 玩家分別在不同地圖中行動。
- A 看到題目，B 看到範例測資。
- A 找到房間密碼格式，B 找到密碼內容。
- A 必須開啟電源，B 才能操作電腦解題。
- 兩人需要同時啟動不同建築內的機關。

## 核心機制

### Top-down 探索與視覺小說互動

平常探索地圖時使用 Top-down。玩家和 NPC、重要物件、資訊點互動時，切換成類似視覺小說的背景、角色立繪與對話框。

### 鬼魂追逐

台達館走廊有鬼遊蕩並追玩家。鬼魂需要提供恐怖壓力，但難度要能支撐 demo，不應讓玩家頻繁卡關。

### 演算法 AC 拿鑰匙

玩家需要完成一個演算法題並獲得 AC 才能拿到鑰匙。系統以預設題目與驗證器判斷 AC/WA，不做完整 Online Judge。

### 雙人合作

A 和 B 分別在台達館、資電館，需要經過重重考驗才能相遇。兩人必須共通合作，才能通關各自樓層。

### AI 對話解謎

使用 LLM 製作 NPC 來控制知識鎖。玩家要在場景中取得線索來問 AI 問題，並透過有技巧和策略的對話套取重要資訊。

## Puzzle Ideas 關卡構想

### 關卡 1：Binary Search 音高 / 節拍

可冀設計。兩人要用唱的互動。

- P1 撿到音樂盒，聽到音高。
- P2 獲得一個節拍。
- 玩家要透過對方資訊，以 binary search 的方式進入有相同音高或節拍的房間。
- 左右房間各有不同節拍或音高。
- 房間結構是 tree。
- 有限制時間。

### 關卡 2：AI NPC 互動 / Prompt Injection

主題是跟助教要分數。玩家不知道助教為什麼扣分，需要透過其他資訊知道自己錯在哪裡。

可能解法：

- 找到助教的把柄威脅他。
- 找到助教的喜好。
- PUA 助教讓他懷疑自己。
- 分數可以影響結局。

參考：

- [Echo Chamber: Context Poisoning Jailbreak](https://neuraltrust.ai/blog/echo-chamber-context-poisoning-jailbreak)
- [Crescendo: Gradual Prompt Attacks](https://neuraltrust.ai/blog/crescendo-gradual-prompt-attacks)

### 關卡 3：陽台手勢合作

地點在陽台，兩位玩家兩兩相望。使用 MediaPipe 或類似 browser pose / hand gesture 技術辨識手勢，讓玩家用身體動作交換訊號或啟動機關。

## High Risk Analysis 高風險分析

### AI 對話解謎是否可控

如果 AI 太容易直接講出答案，遊戲會失去解謎性；如果 AI 太難溝通，玩家又可能感到挫折。

設計方向：

- AI 只能根據玩家已取得的線索回答。
- NPC 有固定角色設定與知識範圍。
- 關鍵資訊不能一次完整揭露。
- 玩家需要用正確問題逐步逼近答案。

### 雙人合作機制

如果合作設計不好，可能會變成一個人在解謎，另一個人只能等待。

設計方向：

- A 和 B 都有各自需要完成的任務。
- 謎題資訊分散在兩位玩家場景中。
- 部分關卡需要同步操作。
- 每位玩家都能影響另一位玩家的進度。

### Top-down 探索與鬼魂追逐

鬼魂追逐會影響遊戲緊張感。太難會一直失敗，太簡單則恐怖感消失。

優先完成：

- 玩家移動與碰撞。
- 鬼魂巡邏與追擊。
- 躲藏或逃脫機制。
- 被鬼抓到後的懲罰與重生方式。

### 演算法題與遊戲流程整合

題目太難會影響節奏，太簡單又失去特色。

可能做法：

- 題目以簡化版演算法挑戰呈現。
- 玩家輸入答案或程式邏輯。
- 系統用預設測資判斷是否 AC。
- AI NPC 可以提供提示，但不直接給完整解法。

## High Value Analysis 高價值分析

### AI NPC 角色個性

每個 AI NPC 可以有不同個性，例如神秘助教、被困住的學長姐、壞掉的課程機器人、不願直接回答問題的幽靈教授。

### 視覺小說式演出

重要對話、恐怖事件或劇情轉折時切換成視覺小說畫面，讓遊戲更有記憶點。

高價值元素：

- 角色立繪表情變化。
- 背景音效與驚嚇演出。
- 關鍵劇情 CG。
- 對話選項影響 NPC 回應。

### 多結局設計

根據玩家解謎方式、是否救出對方、是否問出隱藏真相，可以設計不同結局：

- 普通結局：成功逃離。
- 壞結局：其中一人被困住。
- 真結局：發現台達館異變的真正原因。
- 隱藏結局：成功破解所有 AI NPC 的秘密。

### 成就與收藏系統

玩家可以收集校園中的隱藏文件、錯誤程式碼、鬼魂紀錄與清大傳說，增加重玩價值。

## Similar Games 類似遊戲參考

- Escape Room / 密室逃脫遊戲：場景探索、物品線索、密碼鎖、多階段解謎流程。
- 2D 恐怖探索遊戲如「青鬼」系列：Top-down 探索、鬼魂追逐、不安場景、簡單操作但高壓力的逃跑體驗。
- Doki Doki Literature Club / 視覺小說式互動：角色立繪、對話框、劇情分歧、氣氛轉變。
- Keep Talking and Nobody Explodes：資訊不對稱、合作解謎、溝通壓力、雙方都必須參與。

畫面元素：

- NPC 立繪。
- 對話框。

- 已取得線索列表。
